# Contributing

This repository has one maintainer, and the honest guidance is
unusual, so here it is plainly.

## The contribution this project wants right now: an issue

The scarcest resource at this stage is real-world problem reports.
If wiki-sticky confused you, broke, fought your workflow, or is missing
something you needed — [file an issue][new-issue]. That *is* the
contribution, and it is more valuable right now than a pull request.

Two structured forms are offered:

- **Pollution** — a problem, described as a problem. Say what's
  wrong, who it affects, what it costs while unfixed, and how you'd
  know it's gone. Don't prescribe the fix — a proposed solution is
  welcome as an optional sketch, but the problem statement is the
  contribution.
- **Positive feedback** — it worked? Say so. What you used it for
  and what held up. Usage reports are how a young tool learns what
  not to break.

Free-form issues are fine too; the forms guide, they don't gate.

## Code contributions

Not currently sought. The project is in a single-maintainer stage
where design coherence matters more than throughput; unsolicited
pull requests will likely be declined regardless of quality, which
wastes your effort. If you believe a change is needed, open an issue
first — if the problem stands, the solution conversation happens
there.

## The mission

Everything above serves one thing: solving
[#1](https://github.com/funarchy/wiki-sticky/issues/1) well.
